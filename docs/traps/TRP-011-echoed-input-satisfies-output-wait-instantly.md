# TRP-011 출력 도착을 "화면 행에 마커 포함"으로 기다리면 입력한 코드 행이 마커를 포함해 즉시 통과한다

- 상태: ACTIVE
- 적용 조건: 브라우저 하니스가 `waitFor(rows.some(l => l.includes(marker)))`로 Python 출력(배경 콜백의 `print`, 지연 출력)이 나온 시점을 기다리고, 그 마커가 사용자가 입력한 코드 안에도 들어 있을 때(`call_later(2, print, 'TICK')`의 `TICK`, `print('bg-got', input('bg> '))`의 `bg>`).

## 오해하기 쉬운 신호

- 확인이 PASS로 끝난다. 경과 시간을 재면 2ms처럼 비정상적으로 짧다(기대 ≈2초). 화면 끝을 기록하지 않으면 눈치채기 어렵다.
- 실제로 `input()` 확인 스크립트가 19/19 PASS였고 지연 출력 확인은 `TICK 2ms 뒤`였다. 입력한 코드 행 `>>> import asyncio; ...call_later(2, print, 'TICK')`가 `TICK`을 포함해 기다림이 즉시 끝났다.

## 원인

xterm 화면에는 입력 에코와 출력이 같은 행 목록에 있다. 텍스트 포함 검사는 어느 쪽이 그린 글자인지 구분하지 못한다. TRP-008(부재 확인이 화면 밖 로그를 놓침)의 반대 방향이다(존재 확인이 에코에 걸림).

## 탐지/회피

- 코드 행을 제외한다(`!l.includes("call_later")`). 또는 코드에 없는 글자로 조립한 마커를 쓴다(`"TI" + "CK"`).
- 기다리기 전에 마커 출력이 아직 없음을 단언하고, 경과 시간의 하한도 단언한다(`call_later(2)`면 1000ms 미만이면 실패).
- 시간을 재는 확인은 경과 시간과 화면 끝을 항상 로그에 남긴다.
